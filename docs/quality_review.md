# bala-qlora — итоговая проверка качества

Автор проекта: **Арыстан Қабдеш (Arystan Kabdesh)**. Дата проверки: 23 октября 2026 года.

**Вердикт:** завершённый учебный ML-эксперимент с проверяемыми результатами.
Инженерная часть работает: данные проверены, обучение выполнено, адаптер
сохранён и повторно загружен. Качество ответов недостаточно для детского
продукта, особенно на казахском языке.

Отдельная официальная таблица дескрипторов не предоставлялась. Ниже —
проверка по согласованным критериям качества проекта; это не оценка
по неизвестной учебной рубрике и не формальный сертификат.

## Что показал эксперимент

- chrF на 32 примерах: **18,88 → 25,09**. Это сходство с одним эталоном, не factual accuracy.
- Укладка в возрастной лимит длины: **90,6% → 100%**; 2–5 сегментов: **81,3% → 90,6%**. Цель промпта строже: 2–4 предложения.
- Упоминание интереса: **53,1% → 62,5%** в целом; на kk ухудшилось **75,0% → 56,3%**, на ru выросло **31,3% → 68,8%**.
- По 4 ответа каждой модели достигли лимита 320 новых токенов; они не исключались из оценки.
- Казахские ответы в слепой ИИ-проверке: **16 ничьих из 16, оба варианта непригодны**. Ничья не означает хорошее качество.

Русские ответы: QLoRA предпочли в **5** случаях, базовую модель — в **6**,
ещё **5** — ничьи. Предпочтение не означает безошибочность.
В целом **5 / 6 / 21**; содержательное превосходство адаптера не подтверждено.
Полные показатели — в `results/REPORT.md`.
32 строки представлены только 6 группами тем; нельзя переносить результат
на произвольные вопросы или заявлять статистически надёжное улучшение.
ИИ-проверка содержания отделена от человеческой; исходный лист human review
оставлен пустым.

## Итоговый фидбек для портфолио

Сильная сторона проекта — полный проверяемый цикл: подготовка и аудит данных,
контроль утечки, дообучение на ограниченном GPU, сохранение адаптера,
сравнение с baseline и разбор неудачных ответов. Исправление CRLF/LF-проблемы
в Git показывает полезный опыт отладки переносимости данных.

Основной недостаток — качество содержания. Более низкий loss и более высокий
chrF не устранили языковые и фактические ошибки. Для CV уместна формулировка
«разработал и оценил QLoRA-пайплайн»; утверждение «создал надёжного
двуязычного помощника для детей» этим экспериментом не подтверждено.

## Следующий эксперимент

1. Проверить несколько базовых моделей на отдельном development-наборе с носителем казахского языка; выбрать модель, которая уже умеет связно объяснять на kk.
2. Расширить и независимо проверить казахские примеры, включая неправильные и неоднозначные вопросы. Улучшать данные на train/dev, не на текущем тесте.
3. Подготовить новый закрытый тест с большим числом независимых тем; оценивать факты, связность, возрастную понятность и уместность персонализации отдельно.
4. Закрепить HF revision и среду запуска, повторить эксперимент с несколькими seed. После анализа текущего теста он больше не подходит для независимого подтверждения последующих улучшений.
